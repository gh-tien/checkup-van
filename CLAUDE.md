## Design principles

- **Tokens over literals.** Never hardcode a hex value, font family, or spacing number that exists in `theme.js`/`DESIGN.md`. Reference the token (`C.primary`, `F.sansBold`). If a needed value is missing, add it to `theme.js` and `DESIGN.md` first, then use it.
- **Hierarchy is deliberate.** Size, weight, and color carry meaning. One primary action per view (the blue `heroPrimary`/filled button); secondary actions recede to outline or text. Don't make everything bold.
- **Spacing is a system.** Prefer the 4px scale. Where you extend an existing prototype-derived surface, match its neighbor's padding rather than re-guessing.
- **Type scale is closed.** Use the named families in `F` at the sizes in `DESIGN.md`. Don't invent one-off sizes.
- **Color carries semantics.** `primary` = primary action; `error` = blocked/defect/destructive/send-back; `warning` = awaiting/open-jobs/expiring; `success` = passed/OK/fixed. Never pick a raw color when a role token fits.
- **Restraint reads as quality.** One soft shadow, thin `outline` borders, generous whitespace. Fewer competing accents.

## Accessibility

- **Contrast:** WCAG AA minimum: 4.5:1 for body text, 3:1 for large text (≥24px or ≥18.66px bold) and meaningful UI/graphics. Verify every `on-*` token against its surface.
- **Focus / press:** Interactive elements are `Pressable`; give clear pressed feedback and adequate `hitSlop`.
- **Targets:** Touch targets ≥44×44pt. Rows and pad keys already meet this — keep it.
- **Semantics:** Use `accessibilityRole`/`accessibilityLabel` on icon-only controls (e.g. the header avatar sign-out, search clear). Label every text input.
- **Don't rely on color alone** to convey state; pair with an icon, text label, or shape (status badges carry a word, not just a hue).

## React Native conventions

Target: **React Native (Expo)**, plain JavaScript (no TypeScript, no web DOM, no Tailwind).

### Components & files
- Function components only. Default export, one screen/component per file. `PascalCase.js` for components/screens.
- Keep files co-located under `src/screens` (full screens) and `src/components` (shared: `AppHeader`, `BottomNav`, `Icon`, `Toast`).
- Compose small pieces (a `Stat`, a `Legend`, a row card) over one mega-component. Local sub-components at the bottom of the file, like `DashboardScreen.js`.

### Styling
- Style with `StyleSheet.create(...)` at the bottom of the file; pull every color/font from `theme.js` (`C`, `F`, `cardShadow`). No inline literal hex or font names.
- Layout with flexbox and `gap`. Use `ScrollView` with `contentContainerStyle={{ padding: 16, gap: 14 }}` for scrolling screens (see `DashboardScreen`).
- Icons come from the shared `Icon` component (SVG, viewBox 0 0 24 24). Add a new glyph to `Icon.js`'s `PATHS`/`EXTRAS` rather than embedding raw SVG in a screen.

### State & data
- App state is a **singleton `Store`** (`src/store.js`) exposed via React context + `useSyncExternalStore`; read it with `useStore()` and mutate via imperative methods (`s.go(...)`, `s.setState(patch, cb)`). Don't add a second state system.
- Persisted keys live in `PERSIST_KEYS`; call `saveState()` after mutating any persisted slice (fleet/queue/approved/returned/people/config).
- Derive view data in the component (or a small `useX()` hook like `useDash`); don't mirror derived values into stored state.
- Seed/domain data is deterministic in `src/data/model.js` — reuse its shapes (van, doc, history, queue, approved) rather than inventing new ones.

### Naming (UI copy vs. code)
- **UI copy:** Vehicle · Fleet · Rego · Spot-check · Defect · Keyholder · Approve · Send back · Redo · Draw · Pass/Fail · Mark fixed. Roles: Inspector → Manager → Manager+ → Admin.
- **Code identifiers keep legacy spelling** (`vanId`, `genVans`, screen key `'vans'`). Don't rename identifiers to match the copy.

### Accessibility in RN
- `accessibilityLabel` on icon-only `Pressable`s; `accessibilityRole="button"`.
- Respect ≥44pt targets and safe-area insets (`react-native-safe-area-context`, already wired in `App.js`/`BottomNav`).

## Do not

- Do not hardcode hex colors or font names; use `C.*` / `F.*` tokens.
- Do not use magic spacing numbers where a scale value fits; match the neighboring surface otherwise.
- Do not invent font sizes; use the typography tokens.
- Do not add a new component when an existing one can be composed or extended.
- Do not introduce Tailwind, `className`, DOM elements, or TypeScript — this is plain-JS React Native.
- Do not add a second state store; extend the singleton `Store`.
- Do not ship contrast below WCAG AA, or convey state by color alone.
- Do not silently override a recorded decision; reference and update `DECISIONS.md`.
